# Benchmark results

Generated by `python benchmarks/run_benchmarks.py` for molecule 0.2.0. Default configuration, real embedding model (`all-MiniLM-L6-v2`), a fresh store per experiment. Nothing is mocked.

Three documents are used:

- **AGENTS.md** — this repo's own spec. A development set.
- **Handbook** (`corpus/handbook.md`) — a made-up engineering handbook. Also a development set: ranking weights were tuned while looking at it.
- **Firmware notes** (`corpus/blind_firmware.md`) — a different domain, written *after* all tuning was frozen and scored exactly once. This is the number to trust.

"Paraphrased" questions are deliberately worded with almost none of the section's own vocabulary. `0.1 → 0.2` compares the previous release with this one on identical labels.

## 1. Blind test (nothing was tuned on this)

| Query set | n | Top-3 (0.1 → 0.2) | Top-1 | MRR |
|---|---|---|---|---|
| Firmware notes — direct questions | 26 | 100.0% → **100.0%** | 92.3% → **100.0%** | 0.96 → **1.00** |
| Firmware notes — paraphrased | 26 | 42.3% → **88.5%** | 30.8% → **42.3%** | 0.45 → **0.63** |

Relevance labels on the same document: 49/52 real questions were answered (not labelled `low`), and 6/10 off-topic questions were flagged `low`. The off-topic questions that slipped through were all near-domain (for example: "what is the price of the station hardware").

| dense only | 95.0% / 80.0% | 50.0% / 8.3% | 100.0% / 97.9% | 81.2% / 58.3% |

Reading it: meaning (dense) and wording (keyword) each fail alone on paraphrases; together they do not. Query expansion matters on AGENTS.md — the document its synonym clusters were first written against — and not on the handbook, which is why it is treated as a small helper rather than the main mechanism.

## 4. Saying "the docs do not cover this"

| Document | Real questions answered | Off-topic flagged `low` |
|---|---|---|
| agents (thresholds were tuned here) | 31/32 | 12/12 |
| handbook (held out) | 93/96 | 10/16 |

Clearly unrelated questions are always flagged. Questions that *sound* like the document but are not covered by it ("what is our parental leave policy" against an engineering handbook) often are not — a real limit of a small embedding model.

## 5. `mol_context`: answers per token

48 paraphrased handbook questions (full file: 5631 tokens). "Answer recall" = the context contains the phrase that answers the question. **Fill** is the obvious baseline: ranked chunks in order until the budget is full, text cut off at the limit.

| Budget | `mol_context` | Fill the budget | Tokens | `context_excerpt="focus"` | Over budget |
|---|---|---|---|---|---|
| 100 | 72.9% with 94 tok | 72.9% with 98 tok | 4% fewer | 58.3% with 88 tok | 0 |
| 150 | 75.0% with 128 tok | 77.1% with 148 tok | 14% fewer | 75.0% with 124 tok | 0 |
| 200 | 77.1% with 177 tok | 77.1% with 197 tok | 10% fewer | 79.2% with 173 tok | 0 |
| 300 | 85.4% with 253 tok | 85.4% with 294 tok | 14% fewer | 87.5% with 250 tok | 0 |
| 600 | 89.6% with 431 tok | 91.7% with 589 tok | 27% fewer | 89.6% with 428 tok | 0 |
| 1200 | 95.8% with 627 tok | 97.9% with 1178 tok | 47% fewer | 95.8% with 626 tok | 0 |

The compiler gives up 0–2 points of recall and spends far fewer tokens as the budget grows, because it stops when the remaining candidates are not close to the best one. It never exceeded a budget. The query-focused excerpt is not better than keeping the head of the section on this corpus, so it is off by default.

## 8. Token cost (every returned token counted)

10 questions against the handbook. Loading the whole file costs **5631 tokens**. Everything Molecule returns is counted — the table of contents, search results and chunk bodies — not just the final chunk.

| Workflow | Tokens per question | Saved vs whole file, per question | Answered | Total for 10 questions | Questions per one whole-file load |
|---|---|---|---|---|---|
| index + search + fetch top-1 (full index) | 1124 | 80% | 9/10 | 11243 | 5.0 |
| budget-fit index + search + fetch top-1 | 555 | 90% | 9/10 | 5552 | 10.1 |
| mol_context(budget=300) | 227 | 96% | 10/10 | 2272 | 24.8 |
| mol_context(budget=600) | 363 | 94% | 10/10 | 3627 | 15.5 |

How to read it. If the agent would otherwise load the file for each question (a new session, or a turn that re-sends it), the per-question column is the saving. If it loads the file once and keeps it for a whole conversation, the last column is the honest one: one-call `mol_context(300)` stays cheaper for about 25 questions. The step-by-step path (index → search → fetch) is *not* cheap on a file this small: the table of contents and the search results cost tokens too, and 0.1 did not count them. That is why `mol_context` exists, and why it is the recommended path. The bigger the docs, the bigger the gap: the cost per question stays flat while the whole-file cost grows.
